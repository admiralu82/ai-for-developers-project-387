# Приложение бронирования событий в календаре

Система бронирования времени для событий различных типов с веб-интерфейсом и REST API.

## Часовые пояса (конвенция)

Все отметки времени хранятся и передаются строго в **UTC** (ISO 8601, суффикс `Z`):

- Backend фиксирует `process.env.TZ = 'UTC'` (первая строка `apps/api/server.js`), в `Dockerfile` задан `ENV TZ=UTC`.
- `startTime`/`endTime` в API и в `db.json` — строки вида `2026-08-28T10:00:00.000Z`.
- Рабочие часы (`9:00-18:00`), границы дня и лимит 14 дней трактуются в UTC.
- Параметры `?date=YYYY-MM-DD` трактуются как календарный день в UTC.
- Frontend отображает время в UTC (`timeZone: 'UTC'` в `toLocaleString`), даты в пикере — UTC-даты.

Не использовать локальные геттеры (`getHours`, `getDate`, `setHours`) для бизнес-логики — только `getUTC*` / `Date.UTC`.

## Особенности

- 📅 Бронирование событий с выбором типа, даты и времени
- 🚫 Автоматическая проверка пересечений временных окон
- ⏰ Ограничение бронирования до 14 дней вперед (настраивается)
- 👥 Страница администратора для управления бронированиями
- 🎨 Современный интерфейс с теплой цветовой палитрой
- 📊 Статистика бронирований в реальном времени

## Быстрый старт

### 1. Установка зависимостей

```bash
cd apps/api
npm install
```

### 2. Настройка (опционально)

Скопируйте `.env.example` в `.env` и настройте параметры:

```bash
cp .env.example .env
```

Параметры можно изменить в файле `apps/config.js`:
- `maxBookingDaysAhead` - максимальное количество дней для бронирования вперед
- `workingHours` - рабочие часы
- `timeSlotInterval` - интервал временных слотов


### 3. Запуск сервера

```bash
cd apps/api
npm run dev
```
Сервер запустится на `http://localhost:3000`

### 4. Открытие приложения

### Структура проекта Backend:
- apps/api/server.js - Express.js сервер со всеми эндпоинтами
- apps/api/storage.js - обработчики JSON файлового хранилища
- apps/api/package.json - конфигурация проекта
- apps/config.js - настройки приложения и типы событий по умолчанию

## API Endpoints
- ✓ GET /api/event-types - список типов событий
- ✓ POST /api/event-types - создание типа события
- ✓ GET /api/event-types/:eventId - получение типа события
- ✓ PUT /api/event-types/:eventId - обновление типа события
- ✓ DELETE /api/event-types/:eventId - удаление типа события
- ✓ GET /api/events - список бронирований (с фильтром по дате)
- ✓ POST /api/events - создание бронирования
- ✓ GET /api/events/:eventId - получение бронирования
- ✓ PUT /api/events/:eventId - обновление бронирования
- ✓ DELETE /api/events/:eventId - удаление бронирования
- ✓ GET /api/available-slots - доступные временные слоты
Бизнес-логика:
- Проверка пересечений временных окон
- Ограничение бронирования на 14 дней вперед
- Валидация рабочих часов (9:00-18:00)
- Автоматическая генерация временных слотов с интервалом 30 минут
- Инициализация типов событий по умолчанию при первом запуске
Валидация:
- Все обязательные поля проверяются
- Проверка формата даты и времени
- Минимальная/максимальная длина строк
- Ограничения на продолжительность событий (10-120 минут)
- Коды ошибок согласно OpenAPI спецификации (400, 404, 409)


## Процесс бронирования

1. **Выбор типа события** - пользователь выбирает тип события (консультация, встреча, мастер-класс и т.д.)
2. **Выбор даты** - выбирается дата в пределах допустимого периода
3. **Выбор времени** - отображаются только доступные слоты без пересечений
4. **Заполнение данных** - ввод контактной информации
5. **Подтверждение** - создание бронирования

## Валидация

- Проверка на пересечение временных окон
- Ограничение бронирования на 14 дней вперед (настраивается)
- Валидация обязательных полей
- Проверка существования типа события

## Типы событий по умолчанию

- **Консультация** - 60 минут
- **Короткая встреча** - 30 минут
- **Мастер-класс** - 120 минут
- **Собеседование** - 45 минут

Типы событий настраиваются в `apps/api/event.json`
