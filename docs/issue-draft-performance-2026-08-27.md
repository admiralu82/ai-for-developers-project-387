## Деградация производительности: LCP выше порога, риск по INP (замер 2026-08-27)

Замер Lighthouse 13.4.1 от 2026-08-27 (`lighthouse-report.json`, https://ai-for-developers-project-386-gsc2.onrender.com/):

| Метрика | Значение | Порог "хорошо" | Отклонение |
|---|---|---|---|
| LCP | 2731.6 ms | ≤ 2500 ms | +9.3% сверх порога |
| CLS | 0.006 | ≤ 0.1 | ок |
| INP | n/a в lab (TBT 4 ms; Max Potential FID 1018 ms) | ≤ 200 ms | риск по длинным задачам |

Примечание: `docs/performance-baseline.md` на момент замера отсутствовал — сравнить с предыдущим базовым уровнем было невозможно; базовый уровень зафиксирован этим замером. Деградации >10% относительно предыдущего замера не зафиксировано, но LCP превышает порог CWV, а длинные задачи создают риск плохого INP в полевых условиях.

### Вероятные причины (коммит 9eb3833 "page-speed-update")

1. **LCP: рендер-блокирующий Google Fonts** — `apps/web/index.html:8-10`: css2-ссылка блокирует рендер, шрифты (4 файла, ~108 KB) начинают грузиться только после CSS (~1.7 с), задержка LCP ~300 мс (оценка Lighthouse `server-response-time`/шрифтовый каскад).
2. **LCP: SPA-рендер после загрузки/выполнения JS** — бандл 102 KB (`index-BsB5XWPg.js`), LCP-элемент рисуется только после выполнения скрипта; TTFB документа 380 мс добавляет задержку.
3. **INP-риск: длинные задачи 1018 ms и 475 ms** в основном бандле (`long-tasks`), Max Potential FID 1018 ms, main-thread work 2.5 с (Style & Layout 1.08 с, Script Evaluation 1.05 с).

### Рекомендации

- [ ] Самохостить шрифты (Fraunces/Inter, woff2, `font-display: swap`) и подключить их через `<link rel="preload">` вместо внешнего css2; убрать рендер-блокирующую ссылку (`apps/web/index.html`). Ожидаемый выигрыш по LCP ~300-500 мс.
- [ ] Добавить `<link rel="preload">`/`fetchpriority="high"` для критичных ресурсов; рассмотреть инлайн критического CSS.
- [ ] Разбить длинные задачи: отложить инициализацию не-критичных компонентов (`requestIdleCallback`/dynamic import для `/admin` страниц в `apps/web/src/router.js`), чтобы снизить Max Potential FID и улучшить INP.
- [ ] Снизить TTFB (380 мс) — кэширование статики/CDN на хостинге.
- [ ] Настроить регулярный замер (`.github/workflows/page-speed.yml`) и сравнение с `docs/performance-baseline.md`; порог деградации 10%.
