# Пользовательские сценарии для E2E-проверок (Playwright)

## 1. Объект тестирования

Система бронирования времени: Express API (`apps/api`, порт 3000) + Vue 3 SPA (`apps/web`, Vite, порт 5173). Данные хранятся в JSON-файлах (`apps/api/db.json` — бронирования, `apps/api/event.json` — типы событий).

| Маршрут | Страница | Назначение |
| --- | --- | --- |
| `/` | `BookingPage.vue` | Публичное бронирование (4 шага) |
| `/admin` | `AdminPage.vue` | Просмотр, фильтрация и удаление бронирований |
| `/admin/addevent` | `AddEventPage.vue` | Создание и удаление типов событий |

## 2. Бизнес-правила и константы (из `apps/config.js` и `apps/api/server.js`)

- Рабочие часы: **9:00–18:00**, интервал слотов **30 минут**.
- Бронирование не раньше текущего момента и не позже **+14 дней**.
- Длительность типа события: **10–120 минут**, название: **5–100 символов**, комментарий бронирования: **минимум 3 символа**.
- Пересечение временных окон запрещено (API: `409 TIME_CONFLICT`).
- Типы событий по умолчанию (создаются при первом старте): Консультация (60 мин), Короткая встреча (30), Мастер-класс (120), Собеседование (45).
- Количество слотов на свободный день: 60 мин — 17 (09:00–17:00), 30 мин — 18 (09:00–17:30), 120 мин — 15 (09:00–16:00), 45 мин — 17 (09:00–17:00).

## 3. Предусловия и тестовые данные

- Запущены API (3000) и web (5173); `event.json` содержит 4 типа по умолчанию.
- Дату бронирования в тестах брать динамически — **завтрашний день** (для сегодняшнего часть слотов уже в прошлом).
- Перед каждым тестом очищать `db.json` (либо удалять все бронирования через API), т.к. хранилище файловое и общее.
- Удаление в UI использует `window.confirm` — в Playwright обрабатывать через `page.on('dialog')`.

## 5. Инфраструктура тестов (реализовано)

1. **`playwright.config.ts`**: настроены `baseURL: 'http://localhost:5173'`, `globalSetup: './tests/global-setup.ts'` и `webServer` (массив):
   - API: `command: 'npm run dev'`, `cwd: 'apps/api'`, `url: 'http://localhost:3000/api/event-types'`;
   - Web: `command: 'npm run dev'`, `cwd: 'apps/web'`, `url: 'http://localhost:5173'`.
   - Проекты: браузерные `chromium`/`firefox`/`webkit` (игнорируют `api.spec.ts`) и отдельный проект `api` (только `tests/api.spec.ts`, выполняется один раз без браузера).
2. **`tests/global-setup.ts`**: перед запуском удаляет все бронирования и восстанавливает 4 типа событий по умолчанию (идемпотентно).
3. **`tests/helpers.ts`**: общие утилиты — `API_BASE`, `isoDateDaysFromNow`, `projectBookingDate`, `clearBookingsByComment`, `getEventTypeIdByTitle`, `createBookingViaAPI`, `setDateInput`, `fillBookingForm`, `submitBooking`, `formatAppDate`.
4. **Изоляция данных**: `db.json` общий для всех тестов. Схема: у каждого проекта своя дата (chromium D+1, firefox D+2, webkit D+3, api D+4 — `projectBookingDate()`), у каждого теста — своё непересекающееся временное окно и уникальный комментарий. Распределение окон на дату браузер-проекта: 09:00 BOOK-01, 10:00 BOOK-03 (только просмотр), 11:00 BOOK-02, 13:00 SLOT-02, 15:00 BOOK-05, 17:30 BOOK-04; на дату проекта `api`: 09:00 API-02, 10:00–12:00 API-04. Очистка — точечная, по комментарию теста (`clearBookingsByComment`), плюс полная очистка в globalSetup. Это позволяет тестам выполняться параллельно без конфликтов; при добавлении новых мутирующих тестов выбирать свободные окна (например, 12:00, 16:00) либо переводить сьют на `--workers=1`.
5. **Особенности приложения** (учтены в тестах):
   - форма бронирования сбрасывается через ~10 с после успешного создания (`setTimeout 10_000`);
   - сообщения об успехе/ошибке отображаются внизу страницы, после шага 4;
   - в WebKit `fill()` поля `type="date"` не надёжно триггерит `v-model`/`@change` — используется `setDateInput` (значение + синтетические события `input`/`change`).
6. Для сценариев с `confirm()` регистрировать `page.on('dialog')` до клика по кнопке удаления.
7. Даты в тестах вычислять относительно текущего дня, время слотов проверять в локальном формате «ЧЧ:ММ» (09:00, 13:30).
8. Потоковые сценарии (BOOK-01 → BOOK-02, TYPE-02 → бронирование новым типом) оформлять как отдельные `test` с последовательными шагами внутри, а не как зависимые тесты.
9. Сьют 4.5 (типы событий) мутирует глобальное состояние (`event.json`) — его тесты выполнять последовательно, либо восстанавливать типы по умолчанию после каждого теста.
